# tera-simulator

テラエナジーでんきの**電気料金シミュレーター**を置いているリポジトリです。

初めてこのリポジトリを触る人が、5分で全体像をつかめることを目指して書いています。

---

## このリポジトリがやっていること

やっていることは、実はとてもシンプルです。

**HTMLファイルを置くと、GitHub Pages がそのままWebページとして公開してくれる。** それだけです。
ビルドもサーバーもデータベースもありません。

- 公開URL：https://tera-energy-jp.github.io/tera-simulator/
- 公開の仕組み：`main` ブランチのルートに置いたファイルが、そのまま公開される
- 各ページのURLは「公開URL＋ファイル名」
  例：`https://tera-energy-jp.github.io/tera-simulator/staff-teiatsu.html`

### 自動で動いているものは、何もありません

GitHub Actions のワークフローは1つもありません（`.github/workflows` フォルダ自体がない）。
定期実行されるジョブもゼロです。動くのは、ファイルを置いたときのPages公開だけ。

これは「シンプルでいいね」という話ではなく、**気をつけないといけない話**です。

料金の単価データは、**HTMLファイルの中に直接書き込まれています**。
だから制度が改定されても、数字は自動では変わりません。
誰かが新しい単価でHTMLを作り直して置き直すまで、**古い数字のまま公開され続けます**。

→ いつ・何を更新するかは [`ops/rate-update.md`](ops/rate-update.md) にまとめてあります。

## 触る前に知っておいてほしいこと

### 1. 大きいHTMLを直接エディタで編集しない

`staff-*` と `school-simulator_*` は1本1.4MBあります。圧縮済みなので、開いて直そうとすると高い確率で壊れます。

特に `TSO_BY_FY`（託送料金）と `LOSS_BY_FY`（送電ロス率）のブロックは、**ツールが自動生成する部分なので手編集禁止**とコード内にも書かれています。
修正は生成元でやって、ファイルごと差し替えるのがルールです。

### 2. ここに置いたものは、全部インターネットに公開される

Pagesはルート直下をまるごと公開します。社内向けの `staff-*` も、**URLを知っていれば誰でも開けます**。
検索避けが入っているのは `taiken.html` だけです。

作業中のファイルや、公開してはいけないデータは置かないでください。

### 3. 入力した内容は、そのブラウザにしか残らない

下書きも顧客プロファイルも、すべて**ブラウザのlocalStorage**に保存しています（`TERA_CASE_DRAFT_v1`、`TERA_CUSTOMER_PROFILES_v1`、`TERA_UTILITY_DATA_v1`、`TERA_OPERATOR_v1` など）。

つまり、**別の端末では見られませんし、キャッシュを消すと消えます**。
シークレットウィンドウでも引き継がれません。「入力が消えた」という問い合わせは、ほぼこれが原因です。

### 4. 追っかけシートの接続先は、リポジトリに入っていない

`staff-*` にある「追っかけシート」へのWeb直送は、**使う人が自分のブラウザで設定パネルにURLとトークンを貼る**方式です（保存先は `TERA_TRACKING_WEB_v1`）。

なのでGAS側を作り直してURLが変わった場合、**リポジトリを直すのではなく、使っている人それぞれに貼り直してもらう**必要があります。
なお、貼るURLは末尾が `/exec` のものです。`/dev` は開発用なので動きません。

### 5. まだ仮の数値がある

低圧の送電ロス率などは、確定値ではなく仮の値が入っています。
そういう項目は画面に「仮・要確認」のバナーが出るようになっています。
何が仮なのかは [`ops/rate-update.md`](ops/rate-update.md) の一覧を見てください。

## 公式サイトへの埋め込みについて

`index.html` と `cs-teiatsu.html` は、**単体で見るページではなく、公式サイトに埋め込まれる部品**です。
ページの高さを親ページに知らせる仕組み（WEBベンダー提供のスクリプト）が入っています。

そのため、「サイトで表示が崩れている」という報告が来たときは、**このリポジトリだけでなく埋め込み先のページ側も**確認してください。原因が向こう側にあることもあります。

## 更新のしかた

ここは**完成したHTMLを置くだけの場所**です。編集と生成は別の環境（`03_v10_source/` 配下のツール群）で行います。

```
別の環境で単価マスタを更新 → HTMLを再生成
        ↓
GitHubにアップロード（Web UIの「Add files via upload」または git push）
        ↓
1〜2分で公開ページに反映される
```

コミットメッセージには、改定内容とバージョンを残す慣習になっています。

```
R7: 追っかけシート Web直送 ＋ 登録パネルUI改訂（v39）
R1-R5改訂一式（v36）: 配布6本を差し替え
```

HTMLの中にも `v36` `v37` のようなバージョンコメントが入っているので、
「今公開されているのがどのバージョンか」はそこでも確認できます。

## 困ったときは

| こんなとき | まず疑うところ |
|---|---|
| 表示されている単価が古い | 単価マスタの更新漏れ。[`ops/rate-update.md`](ops/rate-update.md) の収録範囲を確認 |
| 入力した内容が消えた | ブラウザのキャッシュ削除、別端末、シークレットウィンドウ（上記「3」） |
| 追っかけシートに飛ばない | 各自の設定パネルのURL・トークン。末尾が `/exec` か確認（上記「4」） |
| 公式サイトで表示が崩れる | 埋め込み先ページ側の可能性あり（上記「公式サイトへの埋め込み」） |
| 画面に「仮・要確認」と出る | 仮値の項目。[`ops/rate-update.md`](ops/rate-update.md) の一覧を確認 |
